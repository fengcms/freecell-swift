# 首版实现与验收记录

日期：2026-10-07。

## 实现结果

已完成原生SwiftUI应用、独立规则核心和52张牌面资源导入。首版包括单牌与整组移动、点击与拖放、新局、指定自有编号、重开、撤销重做、启发式提示、保守自动/手动收牌、胜利反馈、暂停计时、存档恢复和中文说明。

用户提供的原App未修改。数字牌面经联系表逐张核验，1～13为梅花，14～26为方块，27～39为红桃，40～52为黑桃。源码资源及最终App内52张图片与原文件逐字节一致。

## 构建及核心验证

当前机器：Apple Silicon；Apple Swift 6.3.3；Command Line Tools及macOS SDK，没有完整Xcode。

- Debug应用构建通过。
- Release应用构建及打包通过，位置为`build/FreeCell.app`。
- 本机临时签名的`codesign --verify --deep --strict`验证通过。
- Debug和Release的16组规则检查均通过。
- 独立验证App已启动，截图检查牌面正确显示、8列及4+4槽位布局可见，中文状态与控件可读。
- 实际写出的独立测试存档可解码，并通过52张唯一牌、历史链及发牌编号一致性验证。

16组规则验证：发牌与复现、固定洗牌牌序、工作列与空当、接牌边界、A/K不循环、基础堆、容量与单牌证明、无空间与乱序组、保守收牌、胜利与无动作、12个种子各80步状态约束、撤销分支及存档往返、损坏存档、完整发牌到52张胜利、手动收牌与历史篡改、0～3个中转空列的递归拆解。

每个整组移动证明都用真实单牌规则逐步执行，并比较最终局面与整组操作结果。随机回归保存固定种子，不依赖偶然测试结果。

## 工程决策与计划调整

1. 没有安装Xcode，也未引入第三方依赖。采用根Swift Package中的应用和核心双目标；Xcode可打开Package.swift，`.app`通过构建脚本导出。
2. 当前工具链未提供Swift Testing/XCTest。测试逻辑使用独立`FreeCellChecks`程序，支持Debug/Release、失败非零退出；不用`swift test`。
3. 牌面通过Swift Package资源Bundle打包，不依赖actool编译Asset Catalog。这也允许只有Command Line Tools的机器构建。
4. 提示快捷键使用⇧⌘H，避免占用系统隐藏应用的⌘H。
5. 存档由后台actor按修订号原子写入；退出等待最新写入。退出保存失败时允许取消退出；坏档先备份，备份失败则停止自动保存。
6. 解码GameState即验证不变量；拖拽携带局面版本，拒绝在撤销/重开后执行过期操作。

## 尚未验证的范围

实际macOS 14设备兼容性、完整VoiceOver朗读及全部键盘/拖放回归尚未验证。界面操作验证时检测到用户同时操作窗口，未继续自动点击，以免干扰当前牌局；因此不把截图检查当作完整UI回归。完整52张胜利流程是在规则核心的可控发牌中执行，不是通过界面人工解完一局。

应用包含相关可访问性标签和减少动态效果支持，但不把这些实现等同于通过专项验收。没有实现完整求解器或保证随机牌局可解；不包含Microsoft编号、云同步、iOS版、发行签名或公证。

## 复验命令

```sh
swift run FreeCellChecks
swift run -c release FreeCellChecks
./scripts/build-app.sh
codesign --verify --deep --strict build/FreeCell.app
open build/FreeCell.app
```

验证已有存档：`swift run FreeCellChecks --validate-archive <存档绝对路径>`。

使用独立存档运行界面：`open -n build/FreeCell.app --args --verification`。正常与验证模式的文件路径见README。
