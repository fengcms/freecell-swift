# 1.1 交互调整与验收记录

本次按用户的五项反馈调整。下列约定替代首版关于滚动牌桌和基础堆禁止取回的描述。

## 实现结果

1. 移除ScrollView。牌面保持264:384比例，由可用窗口宽、高及最长工作列同时约束；重叠间距随尺寸缩放，完整牌列始终位于牌桌区域内。
2. 使用AppKit窗口内拖动。拖动时隐藏来源中的所拖牌，鼠标后的牌面使用不透明背景和100%图像绘制；取消或非法释放时恢复。
3. 选中有序后缀后，拖动完整牌龙，保持工作列重叠间距；提交仍是一个操作、一次撤销。
4. 双击依次寻找：合法基础堆、可接牌的非空工作列、空空当、空工作列。同类按最左侧优先。找不到目标时不改变牌局与步数，牌面短暂晃动；减少动态效果开启时只闪红框。单击按系统双击间隔延迟提交，避免双击第一下单独产生一步；快速点击不同目标会先执行前一单击。
5. 基础堆最上方的一张牌可移回工作列；非空列仍需红黑交替递减，空列可接任意牌。禁止同时取多张、取底下的牌或直接送入空当。该操作跳过当次自动收牌，支持撤销、重做和存档恢复。胜利后也可以取回顶部牌。

纸牌点击、双击和拖动共用规则验证。AppKit牌桌负责输入和显示；GameSession提交状态；FreeCellCore计算合法动作；FreeCellPresentation提供可独立验证的几何布局和命中检测。拖动期间规则状态不变，切换应用、暂停、重开、撤销或调整尺寸可取消未提交拖动。

## 验证结果

- Debug应用编译通过，没有新增并发隔离警告。
- Debug与Release的22组规则和布局检查通过。
- 新检查覆盖基础堆取回的合法/非法边界、双击优先级及最左目标、双击牌组和无目标、取回历史/存档往返、从7张到52张长列在不同宽高窗口中的比例及边界、绘制矩形和命中坐标一致、整组拖动位置限制。
- 使用真实种子41和记录过的合法移动创建独立交互验证存档，启动新版App。截图及可访问性树确认没有滚动区域，全部工作列在窗口内，牌面正常，基础堆牌可作为控件访问。
- 验证窗口中发生用户操作，观察到牌组已移到新列及已收牌状态更新。为避免冲突，未继续自动点击；未把这些观察宣称为完整UI自动回归。
- Release应用打包并通过本机签名完整性检查，版本1.1.0/build 2。

晃动的每一动画帧、拖动中每一帧的视觉效果，以及完整VoiceOver专项仍需人工回归。规则优先级、比例边界与状态不变量已由可执行检查覆盖。

## 复验

```sh
swift run FreeCellChecks
swift run -c release FreeCellChecks
./scripts/build-app.sh
codesign --verify --deep --strict build/FreeCell.app
```

独立UI验证存档生成：

```sh
swift run FreeCellChecks --write-interaction-fixture build/interaction-profile/game-v1.json
open -n build/FreeCell.app --args --verification --verification-directory "$PWD/build/interaction-profile"
```

这些命令使用独立存档。正常存档路径与schemaVersion保持不变，旧版有效存档可以继续加载；新规则只扩展基础堆来源移动，不改变牌面ID、洗牌版本及状态结构。启动新版本前先退出旧版本，避免两个进程同时写正常存档。
