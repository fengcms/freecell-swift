# FreeCell 原生 macOS 游戏开发：系列文章规划

状态：提纲待 Fungleo 确认。确认前不开始撰写各篇正文，也不复制到博客专栏目录。

## 系列定位

这组文章记录一个真实的 Swift/macOS 项目如何从规则与资源规划，逐步长成可以交付给玩家的空当接龙应用。文章以实际做过的选择、用户测试反馈、边界问题和发布过程为主线；代码与结论以仓库实现为准，不把没有验证过的能力写成事实。

**目标读者**：会一些 Swift，想理解原生 macOS 应用如何落地的人；以及关心纸牌规则、交互设计、资源许可、测试和独立发布的开发者。

**阅读方式**：按 FC-00 到 FC-11 顺序阅读是一条完整项目线；各篇也可单独阅读。文章中的代码片段会保持短小，完整实现指向对应 GitHub 文件或版本标签。图示优先使用真实牌桌截图、资源对比图、状态流程和小段代码，不为凑篇幅重复设计文档。

## 篇目规划

### 开篇：先想清楚做什么

1. **FC-00｜从一个纸牌游戏开始：FreeCell 项目目标、范围与开发路线**
   - 讲什么：为什么做这个游戏；首版明确做与暂不做的内容；把需求拆为规则、桌面交互、持久化、视觉、发布；如何用阶段计划和验收条件控制范围。
   - 重点决策：先保证规则与牌局可验证，再逐步完善动画、音频和发行；不在首版引入账号、联网或跨平台复杂度。
   - 依据：`docs/01-FreeCell规则与算法.md`、`docs/03-开发计划.md`。

2. **FC-01｜空当接龙不只是拖牌：把规则变成可验证的状态与算法**
   - 讲什么：52 张牌、8 个工作列、4 个空当、4 个基础堆；合法接牌；整组移动容量；自动收牌边界；基础堆取回这一产品约定。
   - 重点设计：用纯规则函数决定合法性，界面只提交动作；用逐张拆解证明整组移动容量，而不是只凭视觉上“能拖过去”。
   - 依据：规则文档、`Sources/FreeCellCore/Rules.swift`、容量与随机合法操作检查。

### 工程骨架与视觉资源

3. **FC-02｜SwiftUI 不够时怎么办：Swift Package、AppKit 牌桌与职责边界**
   - 讲什么：为什么用 Swift Package 组织核心、呈现层和应用；SwiftUI 与 AppKit 各负责什么；如何让规则层不依赖 UI；牌桌为什么采用自绘。
   - 重点设计：核心状态与会话分开；AppKit 只承接精细鼠标、绘制、动画与原生窗口能力；避免把规则散落在按钮回调中。
   - 依据：`Package.swift`、`Sources/FreeCellCore/`、`Sources/FreeCellPresentation/`、`Sources/FreeCellApp/`。

4. **FC-03｜先确认授权，再美化牌面：免费牌面资源的筛选与视觉迭代**
   - 讲什么：发现原牌面授权不明确后，如何寻找可再分发素材；如何记录来源和许可；如何逐轮处理角标留白、数字大小、暖纸色、梅花形状和 J/Q/K 人像边框。
   - 重点决策：资源许可是发布条件；牌面既要单张看清楚，也要在叠放状态仍露出足够信息；用整副牌预览和真实叠牌截图验收。
   - 依据：`THIRD_PARTY_NOTICES.md`、`App/CardSources/`、`scripts/style-cards.py`、`docs/previews/`。
   - 配图建议：调整前后局部对比、整副牌预览、叠牌状态截图。

### 把牌桌做得稳定、顺手

5. **FC-04｜窗口变大牌不乱跳：纸牌比例、留白与长列压缩布局**
   - 讲什么：为何牌大小由窗口决定，而不是由当前列数决定；底部为长列预留空间；列过长时压缩该列间距；窗口缩放和极端长列的边界。
   - 重点设计：区分牌面尺寸、列间距和每列压缩；绘制、拖放目标和可访问性使用一致几何边界。
   - 依据：`Sources/FreeCellPresentation/BoardLayout.swift`、`BoardLayoutChecks.swift`、`docs/07-固定牌宽与焦点调整.md`。

6. **FC-05｜点击、双击、拖拽和整组移动：桌面牌桌的输入状态机**
   - 讲什么：单击选牌与目标、双击自动移动、右击替代操作、拖动整条牌龙、撤销拖动、空白处取消焦点；双击等待时间造成的体验权衡。
   - 重点踩坑：不能只看系统 clickCount；第二次按下后还要观察抬起时间；鼠标命中必须遵循牌的可见区域和绘制层级。
   - 依据：`Sources/FreeCellApp/GameBoard.swift`、`Sources/FreeCellPresentation/ClickTiming.swift`、`docs/05-交互调整与验收记录.md`。
   - 配图建议：手势状态图、长列暴露区域的命中示意。

7. **FC-06｜移动不是瞬移：把收牌、自动移动与胜利做成连贯动画**
   - 讲什么：单步自动收牌如何表现为连续飞牌；动画关闭或降低速度时如何适配；胜利动画何时触发；动画期间如何阻止旧输入污染新局。
   - 重点设计：规则状态是最终事实，动画序列只负责展示；动画起终点需匹配窗口布局；胜利后新局不能被多余确认打断。
   - 依据：`Sources/FreeCellPresentation/BoardMotion.swift`、`BoardMotionChecks.swift`、`docs/06-动画与全屏验收记录.md`。

### 可靠性与原生体验

8. **FC-07｜撤销、重做与自动存档：让每一步都能回来**
   - 讲什么：牌局历史的提交模型；一次整组移动或自动收牌如何形成合理的撤销单位；原子保存与退出前保存；损坏存档的备份策略。
   - 重点踩坑：恢复坏档时若备份失败，后续设置变化、新开牌局或退出都不能覆盖原始文件；“停止保存”应是显式状态，而非比较错误提示文案。
   - 依据：`Sources/FreeCellCore/GameArchive.swift`、`Sources/FreeCellApp/GameSession.swift`、`Tests/SessionChecks/`、`docs/12-代码审查处理记录.md`。

9. **FC-08｜设置也属于产品体验：快捷键、声音、全屏和多语言**
   - 讲什么：macOS 常见设置入口 ⌘,；语言、动画速度、音乐与音效选项；原生菜单和全屏行为；九种语言、系统语言回退及阿拉伯语 RTL。
   - 重点设计：翻译要覆盖菜单、动态状态、错误、规则、辅助功能和独立 About 窗口；牌桌列顺序不因阿拉伯语文字方向而镜像；设置变化要即时生效并持久保存。
   - 依据：`Sources/FreeCellApp/Localization.swift`、`Translations.json`、`SettingsView.swift`、`docs/10-多语言支持与验收.md`。
   - 配图建议：设置面板九语言对照、阿拉伯语界面、菜单与 About 窗口。

10. **FC-09｜让独立桌面应用可交付：图标、许可、构建与 DMG 安装**
    - 讲什么：应用图标如何进入 Dock；如何构建 arm64 `.app`；临时签名的边界；DMG 中放置“应用程序”快捷方式；ZIP/DMG 校验值；GitHub Release 的附件和安装说明。
    - 重点说明：无 Apple Developer ID 时 GitHub 可以托管应用，但没有公证；首次打开可能需要用户在系统设置中允许；明确仅支持 Apple Silicon 与已声明的 macOS 范围。
    - 依据：`scripts/build-app.sh`、`scripts/package-release.sh`、`App/Info.plist`、`docs/09-GitHub发布准备.md`。
    - 配图建议：DMG 打开后的拖放窗口、Release 下载附件截图。

### 收束

11. **FC-10｜纸牌规则怎么测：从固定牌序到完整胜局和真实存档回归**
    - 讲什么：固定种子与确定性、容量证明、规则边界、随机合法操作不变量、完整 52 张胜局、存档损坏恢复、翻译覆盖、窗口布局与交互边界。
    - 重点设计：测试目标是验证用户可观察的规则和风险，不为覆盖率而堆断言；说明纯逻辑检查与真实 GUI/不同 macOS 设备验收的边界。
    - 依据：`Tests/FreeCellCoreTests/`、`Tests/LocalizationChecks/`、`Tests/SessionChecks/`、README 验收说明。

12. **FC-11｜从“能玩”到发布：项目复盘、取舍与下一步**
    - 讲什么：哪些决策让迭代快，哪些问题来自真实试玩才出现；视觉资源、输入手势、系统行为、翻译与发布的协作关系；现有验收限制与值得继续做的改进。
    - 重点复盘：把用户反馈转成可验证要求；保持规则稳定、逐层打磨体验；发布文档、素材许可和安装体验也是软件质量的一部分。
    - 依据：全系列、Git 历史、`docs/04` 至 `docs/12` 验收与复盘记录。

13. **FC-12｜把游戏成绩做成可信的本地统计**
    - 讲什么：对局生命周期、尝试与稳定身份；胜率、步数、计时和连续游玩的口径；无辅助纪录的资格边界；可合并导入与重置的数据设计。
    - 重点踩坑：种子不等于对局身份；独立统计文件与牌局存档存在结算顺序；旧档的辅助历史不可猜；跨时区活动日不能事后重新分桶。
    - 依据：`Sources/FreeCellApp/StatisticsModels.swift`、`StatisticsStore.swift`、`StatisticsWindow.swift`、`docs/13-游戏统计产品设计方案.md`、`docs/14-游戏统计开发与验收记录.md`。

## 每篇文章的统一结构

建议每篇包含：问题与场景、当时的约束、候选方案及取舍、关键实现或图示、踩坑与修正、如何验证、读者可复用的结论。涉及代码时标明仓库相对路径和适用版本；涉及发布或平台行为时标注实际测试环境。避免把个人项目选择包装成唯一正确的“最佳实践”。
