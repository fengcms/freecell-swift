# FreeCell 开发实战 FC-12｜把游戏成绩做成可信的本地统计

**本文目标**：说明如何为一款单机纸牌游戏建立足够完整、但不打扰玩家的成绩记录。

## 从指标开始，先定义边界

“胜率”看起来只是一道除法，实际要先回答：发牌后没动过算不算一局？正在玩的牌是否进入分母？重开算不算放弃？撤销是否增加步数？如果这些口径不明确，界面上的数字越精确，误导越明显。

本项目把第一次有效局面变化作为开始点。胜率只以胜利和已放弃的对局为分母；未结束局保持未结算。重开继续属于当前对局，但建立新尝试；胜后重开则生成新的统计身份。移动计步沿用牌桌历史游标，撤销和重做作为独立辅助事件记录。

## 统计记录需要自己的身份

种子只能标识一次发牌内容，不能标识一次挑战。同一个种子可能被玩家反复尝试，也可能在不同设备的记录中出现。因此每局都有 UUID，种子与洗牌算法版本则用于分组比较。牌局存档保留这个身份，应用退出恢复后仍能接上同一条统计记录。

旧存档缺少统计身份和提示历史，不能猜测以前的胜负或把未知辅助当成零。升级后的未完局只从第一次有效新操作开始进入统计，并明确标记历史不完整，不参与无辅助成绩。

## 不把累计值当成数据库

只保存“赢了 24 局、玩了 12 小时”会让导入、重置、去重和趋势分析变得困难。统计文件保存牌局、尝试和有唯一 ID 的操作/活动片段，再由这些记录计算摘要。重复导入同一片段可以去重；不同来源对同一个已结算身份给出冲突时，整个合并会停止，而不是悄悄挑一个成绩。

计时按有效前台时间累加，并随自然日边界写入当时的本地日期与时区。后续旅行或修改时区不会把旧时长重新分到新日期。统计文件与游戏牌局存档分开保存；导出的 JSON 不会恢复牌桌，也不带完整移动历史和偏好。

## 无辅助成绩必须写清规则

“无辅助”不是天然统一的赛事标准，本应用把它限定为一类个人纪录：不重开、不看提示、不撤销/重做、不自动选目标、不使用安全收牌、不启用自动收牌，也不把基础堆牌取回。手动移动仍然允许。每次失去资格都记录具体原因，但不会弹窗责备玩家；普通成绩仍然保留。

## 让数据管理保持可逆

导入默认合并，按身份去重；替换和重置都要求明确确认。确认时回车默认为取消，避免不小心删掉记录。当前牌局不会因导入或重置而被替换，但会暂时退出统计周期，避免它稍后获胜又回填到清空的数据中。

数据写入采用原子替换，坏文件会被保留，统计写入会暂停并提示玩家。文件体积、对局数、事件数与单局尝试数都有上限，超限文件整份拒绝。

## 如何验证

先用真实试玩确认一次移动、自动收牌、手动收牌、撤销、重做、重开、胜利、退出恢复和重置的记录口径；再用两份相同 JSON 检查重复合并，用冲突的同 ID 记录确认合并会安全失败。需要特别检查跨午夜时间片、重置后旧局获胜，以及同一牌局重复胜利通知。

这些数字描述玩家自己的游戏过程，不证明某副牌理论可解，也不代表不同牌局之间的公平排名。把计算口径和原始数据一起保存，才能让统计既可读，也可以解释。
