# FreeCell 开发实战 FC-06｜移动不是瞬移：收牌、自动移动与胜利动画

**本文目标**：解释如何在不让动画接管游戏规则的前提下，为自动移牌、安全收牌和胜利提供连贯反馈，并处理暂停、撤销、缩放和减少动态效果等情况。

---

## 一、最终局面和动画过程是两件事

如果动画本身逐帧改变游戏状态，用户在动画中途撤销、关闭窗口或切换牌局时，规则状态就可能停在半路。项目采用另一种方式：核心规则一次性计算最终状态并提交历史；呈现层额外接收一段用于展示的状态序列。

例如安全收牌连续移走五张牌，GameSession 把这一系列中间局面交给 `BoardAnimationRequest`，同时把最终结果作为一次牌局历史提交。动画结束不会再写入新的规则状态。玩家点一次撤销，五张牌一起回来。

## 二、以状态差异生成飞牌路径

`BoardMotionSequence` 比较相邻两个局面，为位置改变的纸牌创建 `CardFlight`，计算起点和终点。动画进度由确定性时间线采样，采用平滑的起停曲线；整组移动时，每张牌按原相对偏移移动，因此牌龙不会被拉散。

动画总时长受步骤数和设置速度影响。收牌很多张时，每张牌缩短飞行时间，避免整个流程拖太久。速度为“无”时直接显示规则最终状态，不播放飞牌，但收牌仍是同一条规则操作。

## 三、动画不能改变布局契约

如果飞行过程中最长列改变，牌的宽度也跟着变化，飞行物的起点和终点就不再在同一套坐标中。布局会按整段动画涉及的状态计算列长上限，牌宽仍由窗口决定，列间距则为展示过程留出必要空间。

同样，胜利提示采用覆盖层，不改变牌桌尺寸；否则最后几张牌还没飞完，提示出现导致窗口布局变化，动画终点就会移动。呈现反馈应尽量不扰动正在播放的几何空间。

## 四、胜利庆祝和系统设置

最后一段飞牌完成后，牌桌从基础堆播放彩纸庆祝。胜利效果和牌局状态分离：全部 52 张牌已归位才算获胜；彩纸只是一个短暂的视觉反馈。用户可以关闭动画，系统的“减少动态效果”也会优先跳过飞牌和彩纸，保留静态胜利状态。

胜利后开始新局不再显示清除进度的确认，因为当前牌局已经结束。正常未完成牌局的新局或重开仍保留确认，以防误操作。

## 五、中断动画时显示什么

动画播放期间，牌桌不会接受新的移动，避免旧序列和新输入同时控制同一张牌。暂停、撤销、重开、新局、应用失活或窗口尺寸改变时，取消正在播放的视觉序列，并立即按当前规则状态绘制。

一个关键约束是：动画取消不能取消已经提交的动作，也不能把半截动画存进档案。存档只保存规则状态和历史；动画 request 是短期 UI 状态。这样窗口关闭后重新打开，玩家看到的是确定的牌局，不是无法恢复的中间帧。

## 六、怎么验证动画

颜色、速度和曲线需要人工看，但时间线本身可以纯逻辑检查：每一阶段有哪些牌飞行、起终点是否正确、进度 0 和 1 的边界、窗口内坐标、整组间距是否保持，以及速度为零时是否没有动画步骤。

项目把几何路径放在 `FreeCellPresentation`，AppKit 视图只按当前时间采样和绘制。这样动画可以在不启动窗口的情况下检查基本数学行为，再通过桌面试玩观察视觉质量。
