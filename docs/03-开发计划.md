# FreeCell 开发计划

状态：首版已实现；2026-10-07。用户已确认开发，P0～P6实现与当前环境可执行的验证已完成。详细验证范围见《04-实现与验收记录》。

## 1. 建议首版范围

macOS 14+原生SwiftUI应用，使用提供的App内一套完整扑克牌图片。实现经典8列/4空当/4基础堆规则、容量受限整组移动、拖拽与点击移动、键盘操作、新局、重新开始、撤销/重做、合法动作提示、可关闭的保守自动收牌、胜利反馈、步数与有效游戏计时、自动存档恢复、中文规则说明。

首版不包含完整求解器、Microsoft牌局编号兼容、在线账号/排行榜、云同步、iOS适配或商业发布流程。核心保持可移植，但不提前实现其他平台界面。

## 2. 实施步骤与完成条件

| 阶段 | 主要工作 | 可审查交付与完成条件 |
|---|---|---|
| P0 环境与资源核验 | 确认Xcode/SDK；生成候选牌面预览；核对花色点数；选择一套图片 | 52张映射清单、预览与资源来源说明；完整性及尺寸通过检查 |
| P1 工程与核心模型 | 创建macOS工程及FreeCellCore包；建立Card/GameState/Location；发牌与不变量 | Debug可构建；固定牌序发牌正确；52张唯一牌及8列分布测试通过 |
| P2 完整规则引擎 | 单牌/牌组验证、容量算法、合法动作枚举、胜利判断 | 移动矩阵及容量边界测试通过；非法动作不修改状态；整组移动可用单牌拆解验证 |
| P3 会话与历史 | 统一提交动作、撤销重做、重新开始、步数与计时 | 状态与历史一致；新动作清空重做；计时暂停行为符合文档 |
| P4 牌桌与操作 | Asset Catalog导入；自适应布局；点击/拖拽/键盘；非法动作反馈 | 52张牌正确显示；移动路径共享验证；窗口缩放可用；VoiceOver基本可操作 |
| P5 辅助与存档 | 启发式提示、保守收牌、胜利反馈、版本化存档、恢复 | 自动收牌可撤销；过期提示不执行；退出恢复、坏档处理、偏好保存通过验证 |

顺序以先冻结规则、再构建交互为原则。P4视觉细节可以在核心稳定后迭代；任何规则变更同步修改测试与说明。

## 3. 关键决策

- 平台默认macOS，最低14以直接使用Observation；若要兼容更旧系统，需要在实施前调整状态观察方案。
- SwiftUI足以支持此52张牌规模；仅在明确的输入或窗口能力不足时增加小范围AppKit桥接。
- 采用固定花色基础堆，按后续用户要求，允许基础堆最上方的一张牌移回工作列，并支持撤销回退。
- 整组移动使用开始时空当与空列的容量，空目标不能同时作为中转列。
- 自动收牌默认关闭；开启后与用户动作合并撤销。
- 资源先核对再导入；不会把整个第三方App作为项目资源复制进去。
- 首版自有可复现牌局；不把随机局描述为必定可解。

## 4. 验收场景

1. 启动新局看到完整52张牌；选牌及目标反馈清楚。
2. 红黑交替递减接牌，空当只能一张，基础堆从A递增；错误动作有反馈且状态不变。
3. 对非空目标与空目标分别验证整组容量上限，包括无空当、一个中转空列等边界。
4. 一次拖动牌组可用一次撤销回退；重做复原；自动收牌也一并回退。
5. “重新开始”恢复相同局，“新局”生成新牌序；提示不承诺必赢。
6. 完成最后一张牌后只触发一次胜利；退出再开恢复局面与历史，不把关闭时间计入游戏时间。
7. 小窗口、正常窗口及全屏都能访问全部牌与控件；键盘和VoiceOver具备基本可用性。
8. 项目可在记录的Xcode版本下构建；资源映射齐全，核心规则不依赖UI。

## 5. 确认入口

已按macOS 14+、SwiftUI、自有牌局编号、默认关闭自动收牌实施。实际工程使用Swift Package双目标组织；牌面作为Bundle资源导入，适配只有Command Line Tools的开发环境。完整求解器与其他平台仍属于后续范围。

当前交付：完整Swift源码、52张牌面、Release应用、构建脚本、16组规则验证程序、设计与使用文档。原App保持原样。实际macOS 14设备测试、VoiceOver朗读及完整键盘/拖拽回归尚未完成，未将这些列为已验证。
