# 游戏统计产品设计方案

状态：已确认；完整范围已进入实现并完成首轮开发。实际实现与验收记录见 [统计功能开发与验收记录](14-游戏统计开发与验收记录.md)。

日期：2026-10-09；修订：基础统计与全部扩展功能合并开发。适用于当前原生 macOS FreeCell 游戏，继承现有规则、设置、九语言及离线使用方式。

## 1. 目标与范围

让玩家知道自己玩了多少局、完成情况如何、最好成绩是多少，并能清空统计重新开始记录。界面应轻量、容易理解，避免让休闲游戏变成强制排名或打卡任务。

本次一次性开发完整统计功能：

- 基础指标：总对局、胜局、已放弃、未结算、胜率、当前及最高连胜、最少步数、最快用时、平均胜局步数与用时。
- 对局历史：最近及全部对局列表、搜索筛选、对局详情和从记录重新挑战。
- 同牌局比较：按编号与洗牌版本汇总普通和无辅助成绩。
- 游玩趋势：最近 8 周、最近 12 个月的对局、胜率和游戏时间。
- 游玩习惯：累计游戏时间、当前与最长连续游玩天数、提示/撤销/重做/重开次数。
- 数据管理：导出、导入、合并、替换与重置。
- 无辅助个人纪录：明确资格条件，独立展示最佳步数、最快时间与胜局数。

以上均属于本次交付，不再划为后续候选。可以按模块分阶段开发和验证，但完成全部模块后才视为本次功能完成。统计全部保存在本机，没有账号、联网或自动上传。完整求解器、理论最少步数、联网排行榜、每日挑战及自动难度评级不在本次范围。

## 2. 指标与计算口径

| 展示名称 | 定义 | 展示示例 |
| --- | --- | --- |
| 总对局 | 至少完成过一次有效牌局操作的独立对局数量，包括当前进行中的对局 | 36 |
| 胜局 | 对局第一次达到全部 52 张归位时记一次 | 24 |
| 已放弃 | 已开始、未赢，玩家确认切换到新牌局或指定另一局时结算 | 11 |
| 未结算 | 尚未赢、也未确认放弃的对局；含当前进行中局及导入后不能恢复游戏的未结算记录 | 1 |
| 胜率 | 胜局 ÷ 已结算对局，即胜局 ÷（胜局 + 已放弃） | 68.6% |
| 当前连胜 | 最近已结算对局连续胜利的数量 | 3 局 |
| 最高连胜 | 历史最长连续胜利数量 | 7 局 |
| 最少步数 | 所有已记录胜局中，首次胜利时最终路线的最少步数 | 46 步 |
| 最快用时 | 所有已记录胜局中，首次胜利时当前尝试的最短有效游戏时间 | 04:18 |
| 平均步数 | 所有已记录胜局步数的算术平均数 | 62.4 步 |
| 平均用时 | 所有已记录胜局有效时间的算术平均数 | 06:35 |
| 累计游戏时间 | 本统计周期内已登记对局的所有尝试有效时间，含胜局、放弃和未结算局；重开前时间不丢失 | 12 小时 35 分 |
| 当前连续游玩 | 按有有效操作的本地自然日计算；今天或昨天为最近游玩日时保留连续天数 | 5 天 |
| 最长连续游玩 | 历史最长连续有效游玩日数量 | 12 天 |
| 提示/撤销/重做/重开 | 已登记对局中发生的各类有效事件累计值，跨重开尝试累计 | 18 / 42 / 6 / 8 |
| 无辅助胜局 | 满足第 9.8 节资格条件的胜局数，包含在普通胜局总数中 | 7 |

胜率只计算已经结算的对局，避免尚在进行的一局让胜率临时下降。没有已结算对局时显示“—”，不显示 0%；有已放弃局而没有胜局时显示 0%。没有胜局时，最佳及平均成绩显示“—”。

“最少步数”是玩家取得过的最好成绩，不表示求解器证明的理论最优。不同牌局难度、自动收牌设置和重开次数可能不同，因此这些是个人游玩记录；同编号比较和无辅助分组帮助了解差异，不宣称公平竞技排名。

### 2.1 什么是开始一局

发牌、打开应用、选牌、请求提示、无效拖动、无法执行的收牌和修改设置都不算开始。第一次产生有效局面变化后才纳入总对局：包括合法移动和实际收取纸牌。

若第一次操作随即达成胜利，应在一次记录中完成“开始 + 胜利”。已经开始的一局即使撤销到零步，也不会重新变成未开始。

### 2.2 步数

沿用现有游戏显示口径：一次成功提交的玩家动作计一步；由该动作触发的一批自动收牌合并计入该步。手动批量收牌计一步。撤销、重做本身不额外计步，胜利成绩取首次胜利时历史游标对应的最终路线长度。

因此该指标不是鼠标点击总次数，也不是逐张搬运纸牌的数量。无效操作、选牌和提示不计步。本次另行统计提示、撤销、重做和重开事件，不将其混入最终胜局步数，详情中同时展示两种口径。

### 2.3 用时

与现有牌局计时一致：应用处于前台、没有暂停、尚未胜利时累计；应用失活、手动暂停、退出应用及系统睡眠间隔不计入。仅仅没有移动鼠标不算暂停，本次不增加自动闲置检测。

最快时间和平均时间使用首次胜利时的牌局计时值。自动动画不额外改动计时规则；胜利以规则状态提交为准，不等待彩纸或飞牌结束。

### 2.4 重开、同种子与尝试

未赢时“重开本局”继续属于同一对局，不增加总对局、不记放弃、不打断连胜，但建立一次新的尝试；游戏现有步数和计时归零，最终成绩取成功尝试的步数和时间。重开次数与各次尝试的用时在对局详情中展示，汇总计数跨尝试累计。

已经赢过后“重开本局”，视为使用相同种子开始一局新挑战；第一步前不计入总对局。通过指定编号重新发同一个种子，同样是新对局，不能仅用种子作为唯一标识。

这样统计允许玩家反复练习同一副牌；成绩并不代表一次不重开的挑战。本次另外提供“无辅助”分组，要求从首次发牌开始且未重开，具体见第 9.8 节；普通成绩继续允许重开与辅助功能。

## 3. 对局生命周期与边界行为

每局具有持久的独立身份，状态为“未开始 / 进行中 / 已胜利 / 已放弃”。导入未完成记录显示“未结算（仅记录）”，属于统计状态，不能据此恢复牌桌。同一种子可以对应多局，恢复原存档必须保留原身份。

| 场景 | 统计行为 |
| --- | --- |
| 新发牌后立即再新开 | 原局没有有效动作，不结算、不计放弃 |
| 进行中确认新局或指定牌局 | 原局记已放弃；新局直到首个有效动作才计入 |
| 取消新局/重开确认框 | 不改变统计 |
| 暂停、关闭应用、正常退出 | 保留进行中，恢复后接着统计，不算放弃 |
| 进行中重开 | 同一对局新尝试，不记失败或放弃 |
| 第一次获胜 | 记胜局、更新连胜、更新最佳与平均成绩 |
| 胜利动画重复播放/重复通知 | 不重复记胜局 |
| 胜后撤销、重做或取回基础堆牌 | 该局已结算，成绩保持首次胜利时的记录，不追加第二个胜局 |
| 撤销到胜利前再赢 | 同上，不刷新最佳成绩 |
| 无合法移动 | 不自动判失败；玩家仍可撤销、重开或以后继续 |
| 恢复失败/存档损坏 | 不把数据异常记为玩家放弃；保留可恢复的统计 |
| 胜后点击新局 | 保留胜局结果，新局按第一步规则开始 |

进行中一局不打断连胜；只有确认放弃一局才把当前连胜置零。最高连胜保留。统计重置后两者均归零。

## 4. 面板与入口设计

### 4.1 打开方式

- 工具栏加入“统计”按钮，图标建议使用 `chart.bar`。
- 菜单“牌局 → 统计…”提供同一入口，建议快捷键为 ⇧⌘S。
- 开启“功能按钮后显示快捷键”时，统计按钮显示对应快捷键。
- 使用独立的原生统计窗口；重复点击只将已有窗口带到前台，不生成多个窗口。

窗口可在游戏进行中打开，数值实时更新，不因打开统计而强制暂停。关闭游戏主窗口仍沿用现有退出行为，不由统计窗口额外维持一个后台游戏进程。

### 4.2 信息层级

建议默认宽度约 860、高度约 680，可调整窗口大小；以现有绿色牌桌为关联色，主体采用系统面板风格。采用“总览 / 对局 / 牌局纪录 / 趋势”四个标签页，窗口内可以滚动，主游戏牌桌仍保持无滚动条。

“总览”分为三块：

1. **总览**：胜率最醒目；并列展示总对局、胜局、已放弃。若有未结算对局，区分“当前进行中”和“仅有统计记录”的数量，避免误以为导入可以恢复牌局。
2. **个人纪录**：最少步数、最快用时、最高连胜。最少步数和最快时间下方显示相应牌局编号及达成日期；两项可能来自不同牌局。
3. **游玩习惯与平均值**：当前连胜、平均步数、平均用时、累计时间、连续游玩天数及辅助操作计数。底部显示“统计开始于 YYYY-MM-DD”和“胜率仅计算已结束对局”的口径说明。

数字采用便于比较的等宽数字字体；颜色不作为唯一信息表达方式。总览不用饼图；趋势页用简单柱状图/折线及对应数据表。每页的筛选和详细设计见第 9 节。窗口底部提供“导出…”“导入…”与“重置统计…”；重置采用弱化的危险操作样式，避免与关闭窗口混淆。

### 4.3 空数据和失败状态

首次使用显示“完成一局，开始积累你的记录。”，计数为 0，尚无数据的胜率与纪录为“—”。不得用虚构示例值填充实际界面。

统计加载/保存失败时，在面板中展示简短提示及“打开数据目录”入口；牌局仍可玩，避免宣称失败写入已经成功。数据问题不触发统计清零。

### 4.4 胜利反馈

首次胜利且刷新最佳成绩时，在现有胜利提示中增加简短标签：“新的最少步数纪录”或“新的最快用时纪录”；同时刷新连胜。并列纪录也可出现，但不再额外弹出模态对话框。

与原纪录相同视为追平，保留原纪录的日期和编号，本次不显示“新纪录”。首次记分胜局建立最佳成绩，可显示“首个胜局已记录”。符合无辅助资格时，可以显示“无辅助纪录”；胜利区只保留简短提示，详细成绩在统计窗口阅读。

## 5. 重置统计

统计面板底部设置“重置统计…”按钮，视觉上与普通阅读功能分隔。

确认框：

- 标题：“重置所有统计？”
- 文案：“所有统计、对局记录、趋势和个人纪录将被清除。当前牌局和游戏设置保留。”
- 按钮：“取消”“重置统计”。
- Esc 或 ⌘C 取消；回车默认取消，避免误触造成数据清除；重置通过明确点击或按钮焦点操作确认。

只有重置文件成功写入后才清空显示，并刷新“统计开始日期”。写入失败保持原统计，显示错误。

### 5.1 重置时正在玩的牌局

为了不把重置前的动作和胜利重新计入，当前这局在重置后继续可玩，但不再纳入新统计。面板显示“当前牌局未计入；下一局开始记录”。新局或重开后启用新的统计周期；该局被排除期间的时间、操作和活跃日期也不计入。重开重新纳入的局不具备无辅助资格，因为不是未经查看的首次尝试。

胜后重置再撤销、重做也不得让已赢局重新计分。统计重置只影响统计数据，不改动牌局的撤销历史、计时或偏好。

## 6. 本地数据与可靠性要求

统计数据建议使用独立版本化文件 `statistics-v1.json`，保存在与游戏存档相同的 Application Support 目录中；偏好、牌局、统计分别管理。实现时需要为牌局补充稳定的统计身份，兼容读取旧档。

数据需要保留完整统计记录，不能只保存累计计数。至少包括：

- 数据格式与指标口径版本、统计周期身份、当前周期开始时间和数据来源标识。
- 对局独立 ID、种子（以十进制字符串保存避免跨工具数值精度丢失）、洗牌版本、首次登记/结算时间、状态、迁移或导入来源标记。
- 尝试 ID、起止时间、有效用时、最终路线步数、提示/撤销/重做/重开事件及使用辅助的资格标记。
- 带唯一 ID 的每日活动片段：有效操作次数、累计有效时间、本地日期、当时的时区和 UTC 时间。
- 当前对局身份、结算去重信息、运行中计时片段和保存修订；最佳纪录、汇总及趋势可从记录重建并缓存。

原始记录不因历史列表分页或图表只显示 8 周而删除。正常使用不自动截断历史；数据量增大时按需索引和分页。导入文件设置明确体积/记录数限制并提示超限，不静默截断或只合并前一部分。

“胜局登记”必须幂等：同一对局在同一统计周期只能结算一次。牌局文件和统计文件分别保存会有中断窗口，实现时需要设计可重试的结算记录或事务日志，保证退出、崩溃后不会漏记或重复记分；仅在视图看到胜利时加一不足以满足这一要求。

采用原子写入和有序更新。统计损坏时先保留原始文件，恢复失败则暂停统计写入；不能直接用空统计覆盖。无法确认进行中牌局身份时应保留既有累计值、标记异常，不凭种子猜测并补算放弃。

独立验证实例必须使用独立统计目录，与真实玩家记录完全隔离。只写本机文件，不发送用户成绩或牌局数据到第三方。

## 7. 老用户升级

不扫描历史推出玩家过去总共赢过多少局：当前存档只有有限历史，不能可靠重建过去统计。

- 已经获胜的旧档：可恢复正常游戏，但不补记历史胜局；新局开始建立统计。
- 尚未获胜且已操作的旧档：在升级后首个有效操作时纳入一局进行中；完成时按当时完整牌局步数和计时记录。面板以升级后的登记日期作为统计开始日期，不伪造原开局日期；其过去的提示/撤销/重开数据无法还原，详情显示“部分操作记录未知”，不参与无辅助纪录。累计游戏时间只加入升级后实际采集的时间，不拿旧档总时长重复补算。
- 没有有效动作的旧档：按正常首次操作开始规则处理。

面板第一次打开可显示一次简短说明：“统计从此版本开始记录，过去的胜局不会补计。”不强制弹框。

## 8. 本地化与可访问性

延续现有九种语言，包括菜单、指标、解释、空状态、纪录提示、重置确认和错误信息。数字、百分比及日期使用当前界面语言的格式。

阿拉伯语文字采用 RTL，数字和牌局编号保持可读；对较长的法语、德语标签允许换行，避免挤压数字。每项指标提供辅助功能标签和值，并让重置、导入导出、筛选、表格与确认框支持键盘操作。趋势图同时提供可访问的数据表，不依赖颜色区分胜局和放弃。最少步数和最快时间的详细元数据可通过辅助文本读取。

## 9. 本次完整功能的详细设计

### 9.1 对局历史

“对局”页按最近登记时间倒序展示全部已开始对局，默认每页 50 条，支持加载更多。列表包括开始日期、牌局编号、结果、最终步数、最终尝试用时、累计用时及无辅助资格；未结束局没有最终成绩，用“—”表示，并展示当前已记录进度。

支持按结果（全部/胜利/放弃/未结算）、成绩类别（全部/无辅助）、开始日期范围筛选，按牌局编号精确搜索。筛选只影响页面和页面内摘要，不影响总览全局统计。结果为空时区分“暂无记录”和“没有符合条件的记录”。

详情展示首次登记与结束时间、完整种子及洗牌版本、首次胜利成绩、每次尝试用时、累计用时、操作计数、无辅助不合格原因、迁移/导入标记。使用过的辅助只展示事实，不评价玩家表现。

“重新挑战此局”按现有新局确认路径发出相同种子，并建立新对局身份；当前有未完成局时依然要确认放弃。洗牌版本不受当前程序支持时仅查看，不错误地用当前算法冒充同一局。本次不实现操作录像回放，因为统计文件不保存完整局面与移动路线。

### 9.2 按牌局编号比较成绩

“牌局纪录”页以“洗牌算法版本 + 种子”分组，显示挑战次数、胜局、已放弃/未结算、该编号胜率、普通最少步数/最快时间、无辅助最少步数/最快时间及最近挑战日期。

每组可以展开所有对局，或用编号搜索直接定位。支持按最近挑战、挑战次数、种子排序。不同编号之间不以步数或时间评价难度。最少步数和最快时间可能属于两次不同胜局，必须分别保留日期及来源对局；不要展示成一条实际不存在的“最佳综合成绩”。

普通与无辅助成绩可以切换查看。未结算及放弃对局计入挑战次数，但不进入最佳和平均胜局成绩。用时比较内部按完整精度，展示到秒；追平时按 UTC 达成时间、再按对局 ID 稳定选取最早纪录。

### 9.3 周/月趋势

“趋势”页提供“最近 8 周”和“最近 12 个月”，每个周期可查看：开始对局数、胜局/放弃局、已结束胜率、有效游玩时间及活跃天数。默认同时显示胜局与已放弃柱状图，胜率和时间通过指标切换；图下提供同口径数据表。

周按周一到周日，月按自然月；当前周/月标注“尚未结束”，不会与完整周期假装等长。没有已结算局的周期胜率为“—”，没有游玩时间显示 0。

开始对局数归入登记日期；胜局/放弃和周期胜率归入结算日期；时间按每日活动片段拆分。跨周牌局可以在前一周开始、后一周获胜，这是明确口径，不强求每周满足开始数等于结束数。

活动采集时固化本地日期和时区，结算也保存当时本地日期；后来改语言或时区不会把历史日期重新分组。午夜跨日的计时片段拆分，归到各自日期。连续天数使用固化的日历日期，旅行时可能合并同一日期，不尝试按 24 小时推算“真实连续”；面板说明该日历规则。

### 9.4 累计游戏时间

总览展示累计时间，详情展示单局所有尝试累计时间，趋势按日期展示分布。统计从该局登记开始采集，包含当前局、放弃局和未赢重开前的有效时间；重开会清零界面当前尝试计时，但不能减少已经累计的统计时间。

应用在前台且未暂停、未首次胜利时采集，与现有有效计时条件一致。胜后撤销或取回牌时，该局已经结算，后续练习不继续计入统计；需要新局或重开建立新挑战。未操作就更换的未开始局不记录时间。

退出、暂停、重开、跨日及定期保存时按片段记账。恢复或导入相同片段使用 ID 与修订去重，避免“每次打开应用又把总时长加一遍”。UI 格式：短时间用 HH:MM:SS，累计长时间用“X 小时 Y 分”，内部保留精度。

### 9.5 连续游玩天数

只要一个本地日期内，对已纳入统计的未结算对局至少有一次有效事件，该日算活跃：合法移动、实际收牌、成功撤销/重做或实际重开。仅打开应用、计时流逝、请求提示、修改偏好不激活一天。

最长连续天数由全部活跃日计算；当前连续天数以今天或昨天为末日，昨天玩过而今天尚未操作时不提前清零。最近活跃日早于昨天则当前连续为 0。一个日期无论玩多少局只记一天；提示不会单独刷活跃天数。

不发送打卡通知、不追加奖励、不惩罚断档。导入后依据合并后的活跃日去重重算。

### 9.6 提示、撤销、重做、重开次数

- 提示：调用提示且得到实际推荐时计一次；没有目标不计。它仍不增加游戏步数。
- 撤销/重做：历史游标实际变化时计一次；不可执行的按钮/快捷键不计。
- 重开：已开始、未结算局的重开确认成功时计一次；未开始局不计。胜后重开是新对局，不回写已结算局的计数。
- 自动移动和手动批量收牌：内部记录次数及辅助标记，详情中展示，供无辅助资格解释使用。

计数跨尝试累积，撤销不会把曾发生过的提示或撤销事件消掉。第一步前获得的提示或确认重开先暂存到该对局身份，首次有效操作登记时一起归属；如果始终没有开始就换局，该局不进入统计。它们也会取消这局的无辅助资格，避免先看提示再开始被误判。

统计重置时清除计数。升版前发生的事件不能推测成 0，必须显示未知标记；汇总计数说明仅包括实际采集到的事件，不宣称覆盖旧档所有历史。

### 9.7 导出与导入

导出使用系统保存面板，建议文件名为 `FreeCell-Statistics-YYYY-MM-DD.json`。导出当前统计周期的完整快照，包括历史、当前未结算统计记录、每日活动、计数及必要版本/身份，不包括游戏完整存档、音频/牌面、应用偏好、设备用户名或用户文件路径。导出不会清空或修改统计；文件保存到玩家自行选择的位置。

导入使用系统文件选择面板，先校验格式、支持的版本、唯一 ID、有限非负时间、计数、日期和记录关系，再显示预览：日期范围、记录数量、胜局、未结算数及“合并 / 替换 / 取消”。本次导入上限建议为 64 MiB、100,000 条对局和 1,000,000 条活动/事件记录；超限或不支持格式拒绝整个文件，明确解释，不部分导入。

**合并（默认）**：按独立对局/尝试/活动 ID 去重，不按种子去重。已经结算的对局数据不可更改；未结算记录可由其相同身份的合法新修订更新为结算记录。每日片段按身份及修订去重替换，不能简单相加。导入同一文件多次结果相同。若相同 ID 的结算记录或同修订数据互相冲突，停止整个导入并提示冲突，不随机采用较大成绩；玩家可以取消或明确改选替换。

跨设备记录合并后的连胜按结算 UTC 时间排序，相同时用稳定对局 ID 排序；这表示个人合并历史的时间顺序，不代表每台设备分别玩时的连胜。统计开始日期采用已纳入各来源开始日期中的最早值，记录来源周期，但当前本机周期身份不被合并重置。

**替换**：使用导入记录重建全部汇总、纪录和趋势，显示二次确认“当前统计将被替换，当前牌局与设置保留”。提供“先导出当前统计…”按钮。保存成功才切换显示；失败或取消保留原数据。

导入不恢复游戏进度。外部未完成记录显示“未结算（仅记录）”，保留其累计时间和活动，不算失败，也不影响胜率或连胜。如果与本机当前对局身份一致，必须验证其修订和状态与本地牌局相容；发现不一致则拒绝合并，不能悄悄替换当前牌桌。替换导入后当前本机牌局按重置规则排除，下一新局或重开开始记录，避免拿外部统计推断当前进度。

所有汇总从经过校验的记录重建，不信任 JSON 自带的胜率、平均值或最佳值。导入/替换与重置串行执行，游戏结算事件不能穿插造成丢记录；必要时操作期间暂时阻止新的移动，完成后恢复。

### 9.8 无辅助个人纪录

“无辅助”是本应用的成绩类别，不声称遵循外部赛事标准。普通纪录接纳所有正常玩法；无辅助胜局是其中的子集，总胜局不能重复增加。

资格要求从完整初始牌局开始到第一次胜利，满足：

1. 统计完整采集，非无法还原操作情况的旧档；从未重开该局。
2. 第一步时及已开始后的任一时刻均关闭自动安全收牌；第一步前可以调整设置，开启过后再关掉不恢复资格。
3. 未获得提示、未成功撤销或重做。
4. 未通过双击/右击/回车执行自动目标选择，未使用实际收牌的“安全收牌”按钮。
5. 未把基础堆牌取回工作列。

手动点击或拖拽单牌/有序牌组、手动送牌进基础堆、暂停/继续、关闭后恢复、修改动画/音乐/语言/空位偏好都允许。整组容量仍遵循原规则，不要求玩家逐张搬运。

不提供额外强制模式，也不隐藏现有辅助按钮。首次失去资格后详情显示具体原因；界面不弹出打断提醒。总览可切换“全部 / 无辅助”查看胜局数、最少步数和最快时间；无辅助分组不提供独立胜率，因为辅助是否使用常在对局结束前才确定，强行设分母会误导。

无辅助纪录在同编号比较页同样独立展示。合法导入的完整资格记录可以参加；缺少资格字段的来源按“资格未知”处理，仅进入普通成绩，不能根据计数看似为 0 就假定无辅助。

## 10. 验收标准

1. 发牌但未操作不增加总局数；第一次有效动作只增加一次；无效操作不记。
2. 新局确认取消无副作用；确认放弃正在玩的局只结算一次。
3. 关闭/重开应用恢复同一统计身份，进行中不算失败。
4. 未胜利重开仍是一局；胜后重开属于新的练习局，首步前不增加计数。
5. 移动、自动收牌、手动收牌、撤销和重做使用一致成绩口径。
6. 胜利重复通知、胜后取回牌及重新获胜不重复统计；首次胜利成绩不被追改。
7. 胜率使用已结算分母；计数关系始终满足总对局 = 胜局 + 已放弃 + 未结算；当前可恢复牌局最多 1 局，导入可带来多条仅记录的未结算局。
8. 平均值只取胜局；最佳成绩追平不改变原纪录信息。
9. 重置确认取消不影响数据；确认成功后所有统计及日期更新，牌局与偏好保留。
10. 重置后的当前局不会重新计入；下一局或重开启用新的周期。
11. 读写失败、损坏统计、结算中断、旧档升级都有明确行为，能恢复或提示，不静默丢弃数据。
12. 九种语言、RTL、空状态、长标签、键盘与辅助功能可用；新增窗口不会阻止原有退出保存流程。
13. 历史分页/搜索/筛选不删除原始记录，不影响总览；同编号不同洗牌版本不能混组。
14. 从历史重新挑战产生新身份，遵循新局确认；未知洗牌版本不能被错误重放。
15. 周/月统计分别遵循登记、结算与每日活动日期；跨午夜、跨周、修改时区和没有结束局时显示正确。
16. 重开前用时、放弃及进行中时间保留，保存恢复与重复导入不重复累计；胜后活动不再记账。
17. 连续游玩按有效活跃日去重，今天/昨天及断档边界正确；只提示或打开应用不刷活跃。
18. 辅助计数只记录真实事件，跨重开保留；每项资格条件都会正确取消无辅助资格，恢复/语言/动画变化不会误取消。
19. 无辅助是普通胜局子集；不完整旧档或导入资格未知不会获评无辅助，所有汇总能从原始记录重建。
20. 导出再合并、多次导入、同种子不同身份、未结算转结算、冲突、超限、非法值及替换取消/失败均有稳定行为。
21. 导入未结算记录不冒充可恢复牌局、不算放弃；替换和重置不会修改真实牌局与设置。
22. 用实际较大历史验证分页、图表和导入响应，长任务提供进度及安全取消；所有模块在同一次交付中完成。

## 11. 完整开发与交付顺序

以下是同一次开发的内部阶段，不是将扩展功能推迟到下一版：

1. 冻结对局/尝试/活动/辅助资格模型，设计身份、日期和旧档迁移、结算事务及导入格式。
2. 接入开始、首次胜利、放弃、重开、恢复、计时及辅助事件，完成有序、幂等的本地持久化。
3. 建立全部汇总、同编号分组、连续天数、趋势、普通与无辅助纪录查询。
4. 实现四页统计窗口、详情、筛选、重新挑战、菜单/工具栏入口和纪录提示。
5. 实现导入预览、合并去重、替换确认、导出和重置，并完成异常与大数据量路径。
6. 补齐全部九语言、RTL、键盘及辅助功能，验证全范围统计口径及桌面行为。
7. 更新 README、验收记录和相关博客，重新构建 `build/FreeCell.app`，一次性交付完整功能供试玩。

确认后进入开发阶段；必须完成本方案全部功能后交付，版本号、Git 提交和发布再按试玩结果安排。

## 12. 待确认的完整范围与默认选择

本方案包含原基础指标及原全部扩展候选，不再保留“以后再做”的候选项。建议确认这些主要默认选择：

- 胜率仅计算已结束局；进行中与导入未结算记录不算失败。
- 未赢重开仍属一局，最终成绩取成功尝试；累计用时和辅助计数跨尝试保留。
- 全量历史保留，列表分页；趋势显示最近 8 周/12 个月，日期按采集时当地日历固定。
- 无辅助采用第 9.8 节明确条件，独立纪录，不使用含混的“绝对公平”描述。
- 导入默认合并，按身份去重；可确认替换；统计 JSON 不恢复牌桌。
- 重置/替换保留当前游戏，当前局暂不计入新统计，下一局或重开恢复记录。
- 独立窗口四页，入口 ⇧⌘S，全部功能支持现有九语言。

若需调整上述口径，在确认开发前修改对应条目。此文档的更新不代表已经开始开发。
