审查方式：静态检查源码、项目结构和现有验证程序，并运行规则检查、多语言检查、应用构建及 `git diff --check`。本次只记录审查结果，没有修改实现。

## 结论

规则核心整体清楚，游戏状态、移动规则与展示层分离合理；存档结构有校验和历史一致性检查，现有规则检查覆盖面也较广。建议优先处理偏好变化可能覆盖损坏存档，以及单击／双击边界造成意外自动移动的问题。牌桌重叠区域的命中范围和关于窗口的语言刷新也值得修正或通过界面验证确认。

## 需要优先处理的问题

### P1：偏好变化可能覆盖无法备份的损坏存档

位置：[AppSettings.swift](../Sources/FreeCellApp/AppSettings.swift#L7)、[GameSession.swift](../Sources/FreeCellApp/GameSession.swift#L77)、[GameSession.swift](../Sources/FreeCellApp/GameSession.swift#L94)

`AppSettings.values` 的任意变化都会调用 `onChange`。会话连接后，回调进入 `applySettings()`，更新牌局存档并触发自动保存。若启动时存档损坏，且将其移入备份文件失败，初始化逻辑会设置保存错误，但 `persist()` 没有基于该恢复失败状态阻止写入。之后用户只切换语言或调整其他偏好，也可能把当前新牌局写回原存档路径，覆盖待恢复的损坏文件。

建议把“偏好保存／应用”和“牌局存档”两类副作用分开，并在自动保存及退出保存等所有写入入口统一检查恢复失败状态。增加针对“损坏存档无法备份后修改偏好”的回归检查，确认原存档字节保持不变。

### P1：点击时序边界会把选牌操作变成自动移动

位置：[GameBoard.swift](../Sources/FreeCellApp/GameBoard.swift#L284)、[GameBoard.swift](../Sources/FreeCellApp/GameBoard.swift#L335)

第一次点击会等到系统双击间隔结束后才提交。第二次按下若发生在间隔内，暂存的第一次点击会被取消；若第二次抬起跨过间隔，事件仍可能带有 `clickCount == 2`，随后直接调用自动移动。用户按两次的实际时序可能因此触发移动，而非先选牌。

建议以完整点击序列决定单击／双击，避免仅凭第二次按下或 `clickCount` 状态组合判定。补充测试覆盖第二次按下位于双击间隔内、抬起位于间隔外的情况，并确认第一次点击不会丢失、不会误自动移动。

## 其他值得处理的问题

### P2：重叠牌的鼠标命中范围大于其可见区域

位置：[GameBoard.swift](../Sources/FreeCellApp/GameBoard.swift#L146)、[GameBoard.swift](../Sources/FreeCellApp/GameBoard.swift#L278)

列中每张牌的命中判断使用整张牌的完整矩形，并从最上层开始匹配。下方牌被遮住的区域仍会命中上方牌，因此用户点击下方牌露出的牌面时，可能选到上方牌。

建议让命中框只覆盖每张牌实际露出的部分，最上方牌保留完整高度，并保证绘制、命中及辅助功能可见区域使用一致的几何定义。增加重叠牌点击位置检查，覆盖上下牌的露出边界。

### P2：关于窗口的即时语言刷新尚未接入

位置：[GameLocaleModifier.swift](../Sources/FreeCellApp/GameLocaleModifier.swift#L13)、[FreeCellApp.swift](../Sources/FreeCellApp/FreeCellApp.swift#L10)

语言刷新 modifier 用于游戏窗口和设置窗口。刷新代码只更新这两类窗口标题；关于窗口由独立路径创建，未见其接入该刷新机制。如果用户在关于窗口打开时切换语言，窗口标题或内容可能仍是旧语言。

建议将关于窗口纳入同一个语言变更通知或观察机制，并验证关于窗口打开期间切换语言时，标题、正文和链接标签会同步更新。

## 代码质量与工程规划

- **分层合理。** `FreeCellCore` 集中处理牌、局面、规则、历史和存档；`FreeCellPresentation` 处理布局与动画几何；`FreeCellApp` 负责 SwiftUI／AppKit 集成。这个边界让规则检查不依赖 UI 框架。
- **核心规则实现容易追踪。** 移动先验证、再应用；空当与空列容量、基础堆顺序、牌组顺序都有明确约束。存档校验会重放历史并检查当前游标状态，降低错误档案进入游戏状态的风险。
- **会话对象职责偏多。** `GameSession` 同时管理存档读写、计时、音频、偏好副作用、用户交互、动画请求和状态消息。短期可以维持现状；继续扩展功能时，建议逐步抽出存档协调和计时职责，减少单个对象的改动范围。
- **运行时解析中文消息有脆弱性。** `Localization.render` 通过正则表达式解析中文消息，再映射到翻译目录。这依赖中文句式和标点不被无意改动；建议后续将错误和动态状态改为带参数的消息键，由 UI 层格式化，逐步移除对文案文本的反向解析。
- **验证目标结构清晰。** 规则、展示几何和语言目录检查分开，适合目前不依赖 XCTest 的工程约束。对 AppKit 鼠标事件和多窗口更新的验证仍需要补充界面级回归检查。
